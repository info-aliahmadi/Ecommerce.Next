# Checkout Step Persistence Plan

## Goal
Persist checkout progress (step, payment method, selected address, promo, delivery note) across page refreshes using sessionStorage. Transient and PII data is NOT persisted.

## What to persist
| Field | Why |
|-------|-----|
| `currentStep` | Prevent reset to step 1 on refresh |
| `payment.method` | Preserve payment choice |
| `selectedAddressId` | Remember which address was picked |
| `appliedPromo` | Keep promo code |
| `shipping.note` | Preserve delivery note |

## What NOT to persist
- Contact info (name/email/phone) — recovered from session pre-fill
- `addrForm` — re-fetched from backend or re-entered
- `savedAddresses` — fetched fresh from API
- `isPlacing`, `errors`, `direction` — transient UI state
- `orderNumber` — only set after successful order

## Implementation

### Step 1: Create checkout persist store
**File:** `app/(home)/_lib/store.ts`

Add a new zustand store using `persist` middleware with `sessionStorage`:

```ts
interface CheckoutPersistState {
  currentStep: CheckoutStep;
  paymentMethod: PaymentMethod | null;
  selectedAddressId: string | null;
  appliedPromo: string | null;
  shippingNote: string;
  setCheckoutPersist: (partial: Partial<CheckoutPersistState>) => void;
  clearCheckoutPersist: () => void;
}
```

- Use `name: 'ecommerce-checkout'` as the storage key
- Use `partialize` to only persist the 5 fields above
- Use `storage: createJSONStorage(() => sessionStorage)`
- Add `clearCheckoutPersist()` to reset on order completion

### Step 2: Integrate into checkout page
**File:** `app/(home)/checkout/page.tsx`

1. **Import** the new store
2. **On mount:** Initialize local state from the persisted store (one-time, guarded by ref)
3. **On step change / field change:** Write relevant values back to the persist store
4. **On order completion (step 4):** Call `clearCheckoutPersist()` to clean up
5. **On unmount (optional):** Final sync

Key integration points:
- `currentStep` → read from store on init, write on `goToStep`
- `payment.method` → read from store on init, write on `setPaymentField('method', ...)`
- `selectedAddressId` → read from store on init, write on `handleAddressSelect`
- `appliedPromo` → read from store on init, write on `handleApplyPromo` / `handleRemovePromo`
- `shipping.note` → read from store on init, write on note field change

### Step 3: Handle edge cases
- If persisted `selectedAddressId` no longer exists in `savedAddresses` after fetch, fall back to default address or `'new'`
- If cart is empty on mount, clear persisted checkout data
- If `currentStep` is > 1 on mount but cart is empty or session is unauthenticated, reset to step 1
