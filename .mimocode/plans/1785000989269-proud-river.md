# Fix: NextAuth CLIENT_FETCH_ERROR ("Unexpected token '<'... is not valid JSON")

## What's Happening

The NextAuth client-side `signIn()` function (in `login-form.tsx`) makes a `POST` to `/api/auth/callback/credentials`. Instead of receiving a JSON response, it receives an **HTML page** (starting with `<!DOCTYPE`), which causes the parse error.

## Root Causes (in order of likelihood)

### 1. Backend API unreachable or returning HTML (most likely)

The `authorize()` callback in `options.ts:94-104` calls `AuthenticationService.login()` which hits `https://localhost:7134/Auth/Login`. If:
- The backend server is **not running** — the request may fail, and NextAuth's error handling may return an HTML error page
- The backend returns an **HTML error page** (e.g., from a reverse proxy, IIS, or Kestrel) instead of JSON — the `authorize()` function throws, and the error path returns HTML

**File:** `app/api/auth/[...nextauth]/options.ts` (lines 94-104)

### 2. `pages.signIn` is an absolute URL instead of a relative path

```typescript
// options.ts line 14
pages: {
  signIn: CONFIG.LOGIN_PATH,  // resolves to "http://localhost:3000/login"
},
```

**File:** `config.ts` line 32: `LOGIN_PATH: \`${process.env.NEXT_PUBLIC_FRONT_URL}/login\``

NextAuth's `pages.signIn` should be a **relative path** like `/login`, not a full URL. When NextAuth needs to redirect during the auth flow (e.g., error callback), it redirects to this absolute URL. This redirect can cause the client to receive HTML instead of JSON.

### 3. Placeholder `NEXTAUTH_SECRET`

`.env.development` line 2:
```
NEXTAUTH_SECRET = --------------------AUTH_SECRET----------------------
```

This is not a valid secret. While NextAuth v4 should still return JSON errors with a bad secret, it can cause JWT signing failures that compound the issue.

## Recommended Fixes

### Fix 1: Change `pages.signIn` to a relative path

**File:** `app/api/auth/[...nextauth]/options.ts` line 14

```typescript
// Before
signIn: CONFIG.LOGIN_PATH,  // "http://localhost:3000/login"

// After
signIn: '/login',
```

### Fix 2: Generate a real `NEXTAUTH_SECRET`

**File:** `.env.development` line 2

Replace the placeholder with a real secret. Run:
```
npx auth secret
```
Or manually generate one:
```
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

### Fix 3: Add error handling in `authorize()`

**File:** `app/api/auth/[...nextauth]/options.ts` — wrap the `authorize` bodies in try/catch so that backend failures return `null` (invalid credentials) instead of throwing an unhandled exception that could produce an HTML error page.

```typescript
async authorize(credentials): Promise<User | null> {
  try {
    const authenticationService = new AuthenticationService();
    const loginModel: LoginModel = {
      username: credentials?.username as string,
      password: credentials?.password as string,
      rememberMe: true
    };
    const result = await authenticationService.login(loginModel);
    return result.succeeded === true ? result.data ?? null : null;
  } catch {
    return null;
  }
}
```

Same for the OTP `authorize`.
