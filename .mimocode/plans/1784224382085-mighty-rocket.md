# Plan: Better UX for Unavailable Variant Combinations

## Problem

When a user selects attributes (e.g., Color: Red, Size: XL) and no variant exists for that combination, the current behavior silently falls back to showing the cheapest variant's price/stock. The user sees their selections as "active" but gets product info from a completely different variant. The "Add to Cart" button may even remain enabled if the cheapest variant is in stock — misleading the user.

## Current Flow (broken)

1. `VariantSelector` pre-selects the first option for each attribute type
2. User picks attributes → `handleVariantChange` tries to find a matching variant
3. If no match → `selectedVariant = null` → `activeVariant = selectedVariant ?? defaultCheapest`
4. UI shows cheapest variant's price/stock while user's selections remain highlighted
5. `variantNotAvailable` translation exists (line 681 in en/translation.json) but **never displays** because `activeVariant` always resolves to `defaultCheapest`

## Proposed UX (3 improvements)

### 1. Disable incompatible attribute options

When the user has selected some attributes, compute which remaining options would still form a valid variant combination. Options that can't form any valid combination should be visually disabled (grayed out, opacity-50, cursor-not-allowed, no hover scale).

**Example**: Product has variants:
- Red + S ✅
- Red + M ✅  
- Blue + M ✅
- Blue + L ✅

User selects **Color: Red** → Size **L** should be disabled (no Red+L variant exists), Size S and M remain enabled.

### 2. Show clear "unavailable" state when no match

When the selected combination doesn't match any variant:
- Show the existing `variantNotAvailable` translation: "This combination is not available"
- Disable the "Add to Cart" and "Buy Now" buttons
- Show price range (`$min - $max`) instead of a single variant's price
- Keep the user's selections highlighted (so they can see what they picked)

### 3. Auto-select the first available option on mount

Currently `VariantSelector` defaults to `options[0]` for each type, which may not form a valid combination. Instead, find the first variant that exists and pre-select its attributes.

## Files to Modify

### 1. `app/(home)/products/[id]/_components/VariantSelector.tsx`

**Changes:**
- Accept `variants` prop (already does) and a `currentSelection` map to compute available options
- Add a helper function `getAvailableOptions(variants, currentSelection, attributeType)` that returns which options are still valid given current selections
- Mark unavailable options with `disabled` styling: `opacity-40 cursor-not-allowed pointer-events-none`
- Don't call `onVariantChange` when clicking a disabled option

### 2. `app/(home)/products/[id]/_components/ProductPurchaseSection.tsx`

**Changes:**
- Track `isMatchValid` boolean: `selectedVariant !== null` (explicit match found)
- When `isMatchValid` is false and user has made selections:
  - Show `variantNotAvailable` message
  - Show price range from all variants
  - Disable Add to Cart / Buy Now
- Remove the `activeVariant = selectedVariant ?? defaultCheapest` fallback for display purposes — only use it as initial default
- Pass `selectedKeys` info to `VariantSelector` so it can compute available options

### 3. `app/(home)/products/[id]/_components/ProductActions.tsx`

**Changes:**
- Accept an `isVariantUnavailable` prop
- When true, disable both "Add to Cart" and "Buy Now" buttons

### 4. Translation files (en, fa, ar)

The `variantNotAvailable` key already exists. May need to add a "tryDifferentCombination" key if we want a more helpful message.

## Implementation Details

### VariantSelector: Computing available options

```typescript
function getAvailableOptions(
  variants: ProductVariantDisplayModel[],
  currentSelection: Map<AttributeType, VariantOption | null>,
  targetTypes: AttributeType
): Set<string> {
  // Get the currently selected keys (excluding the target type)
  const selectedKeys = Array.from(currentSelection.entries())
    .filter(([type, opt]) => type !== targetTypes && opt !== null)
    .map(([_, opt]) => opt!.key);
  
  // Find variants that match all currently selected keys
  const compatibleVariants = variants.filter(v =>
    selectedKeys.every(key =>
      v.productAttributes?.some(attr => attr.key === key)
    )
  );
  
  // Return the set of attribute keys that exist in compatible variants for the target type
  const available = new Set<string>();
  for (const v of compatibleVariants) {
    for (const attr of v.productAttributes ?? []) {
      if (attr.attributeType === targetTypes) {
        available.add(attr.key);
      }
    }
  }
  return available;
}
```
